第 21 章 · 第七部 实践与前沿

前沿与展望

这一章不讲「最新最热」，而讲那些正在改变游戏规则的结构性变化： 混合专家怎么把参数和计算解耦、 长上下文为什么不等于长记忆、 「让模型想得更久」为什么会成为第三条缩放曲线、 以及——哪些问题到今天仍然没有解决。 最后一部分是我给学习者的建议：什么会变，什么不会变。

⏱ 约 32 分钟 🎯 建立对前沿方向的判断力，而不是追热点 🧪 1 个交互演示

21.1 一条主线：三条并行的缩放曲线

第 11 章讲过缩放定律：模型越大、数据越多，效果越好。 那条曲线说的是参数和数据。但在过去几年里， 业界发现还有两条同样有效的曲线，而且它们解决的是不同的问题。

这三条路线不是替代关系，而是互补的。 它们分别回答三个不同的问题：

  • ① 更多参数：让模型「知道得更多」。
  • ② 更长上下文：让模型「一次能看更多」。
  • ③ 更长思考：让模型「算得更准」。
判断新技术的框架

遇到任何一个新技术，先问三个问题：

① 它想解决上面哪个问题？ （知识、上下文、还是推理质量？）
② 它把什么换成了什么？ （通常是用内存换速度、用延迟换准确率、用复杂度换成本。）
③ 它的代价什么时候会变成瓶颈？

能回答这三个问题，你就有判断力了；答不出来，就只是在追热点。

21.2 混合专家（MoE）：把参数和计算解耦

先看一个矛盾。

第 11 章的缩放定律说：参数越多，效果越好。 但第 14 章算过：推理成本几乎正比于参数量。 所以「效果更好」和「用得起」这两件事，在稠密模型里是直接冲突的—— 你想要 10 倍的参数，就得付 10 倍的推理费。

混合专家（Mixture of Experts, MoE）打破了这个绑定关系。 它的核心洞察是：

关键洞察

参数是「知识」的载体，计算是「推理」的载体。这两件事本来就不必绑在一起。

稠密模型里，每处理一个 token，所有参数都要参与计算。 但处理「今天天气」这个词和「黎曼猜想」这个词， 真的需要用到同一整套参数吗？显然不是。

所以 MoE 的做法是：把前馈网络拆成很多个「专家」， 每个 token 只激活其中少数几个。 这样总参数量可以很大（知识容量大）， 但每个 token 的计算量很小（推理便宜）。

具体实现只有三步，而且改动的位置很局部—— 只替换 Transformer 块里的 FFN，注意力部分完全不动。

MoE 的代价：三个真实的工程难题

难题为什么常见做法
通信开销 专家必须分布在不同的 GPU 上，token 要「路由」过去再传回来。 这个 all-to-all 通信可能比计算本身还慢 专家并行 + 计算通信重叠； 把通信量控制在可用带宽内（通常是瓶颈所在）
负载不均 某个专家突然被大量 token 选中，它所在的 GPU 就成了拖后腿的那一个 （木桶效应） 负载均衡损失；容量因子（capacity factor）超出部分直接丢弃； 专家复制（把热门专家复制几份）
显存占用 总参数大 → 权重要全部装进显存，即使某次推理用不到 量化专家权重；把冷门专家放在较慢的存储上按需加载
⚠关于 MoE 的两个常见误解

误解一：「MoE 模型有 6000 亿参数，所以比 700 亿的稠密模型强 8 倍。」 不对。决定能力的是「激活参数」和训练数据， 不是总参数。总参数大只意味着知识容量大—— 但如果路由没学好，那些参数可能是浪费的。 比较两个模型时要看：激活参数量、总参数量、训练 token 数、数据质量， 四个一起看。

误解二：「MoE 让推理变便宜了。」 相对而言是的（同样的效果，激活参数更少）， 但它更吃显存，而且引入了通信开销。 在单卡场景下，MoE 往往没有任何优势—— 它的价值在于「用多卡换更好的效果/成本比」。 如果你的部署环境是单张卡，MoE 基本不适用。

21.3 长上下文：窗口变长 ≠ 记忆变好

上下文窗口从 4K 涨到 128K、1M。看起来「记忆问题解决了」。 但实际使用中你会发现两件事：

  • 塞进去的东西，模型不一定用得上。 第 18 章讲过的「中间遗忘区」在这里同样成立， 而且窗口越长越明显。
  • 注意力是 O(n²)。 窗口翻倍，注意力计算量翻四倍，KV Cache 显存也翻倍。 1M token 的窗口在计算上是极其昂贵的。

怎么把窗口撑长

方法思路代价
位置编码外推
RoPE 插值 / NTK / YaRN		 不改模型结构，只调整位置编码的频率参数， 让模型能处理训练时没见过的长度 最便宜。但外推能力有限， 通常还要配一小段「长文本继续训练」
滑窗 / 局部注意力 每个 token 只看附近的 N 个 token， 复杂度降到 O(n·N) 丢失真正的长程依赖。需要和少量全局注意力混合使用
稀疏 / 分块注意力 用固定的稀疏模式（如条带、块状）近似全注意力 实现复杂，效果取决于数据是否匹配假设的模式
线性注意力 / 状态空间模型
Mamba 等		 用递推形式替代注意力，复杂度降到 O(n)， 推理时状态大小固定 表达能力与注意力不完全等价； 混合架构（注意力 + SSM）是目前的主流折中
检索替代记忆
RAG		 不把全部资料塞进窗口，只塞检索出来的相关片段 依赖检索质量。但对绝大多数应用，这是性价比最高的方案
一条实践原则

先问「我到底需要多长的窗口」，再选方案。

如果你的任务是从 200 页文档里找答案， 你需要的不是 1M 的窗口，而是好的检索。 把 200 页全塞进去，既贵又容易漏（中间遗忘）， 还不如检索出 5 段相关内容和问题一起送进去。

真正需要超长窗口的场景是「全局一致性」类任务： 通读整个代码库做重构建议、分析整本小说的叙事结构、 跨多个文档做交叉引用核对。 这些任务的共同点是——你无法事先知道哪一段相关。

21.4 推理模型：把算力花在「想」上

第三条曲线是最晚被发现、也最反直觉的一条。

传统上，提升模型能力的办法是训练时多花算力： 更大的模型、更多的数据。 而推理模型提出的是另一种思路： 训练完就固定了，但推理时可以多想一会儿。

具体表现是：模型在给出答案之前，先生成一段很长的「思考过程」—— 尝试不同解法、检查自己的中间结果、发现错误后回头重来。 对难题多想，对简单题少想。

这张图（示意趋势，源自 test-time scaling 的相关研究）说明了三件事：

  1. 每一条曲线都会饱和。 想得再久，能力上限也是固定的。多想的收益是递减的。
  2. 大模型的上限更高，但起步更贵。 在低预算区间（图的左侧），小模型反而更划算—— 这就是那个交叉点的含义。
  3. 最优策略是「按难度分配算力」。 简单问题不要浪费算力，难问题才值得多想。 这也是为什么推理模型通常有「思考预算」参数。
⚗它和思维链（第 16 章）的区别在哪

思维链是提示技巧：你在提示词里写「让我们一步步思考」， 模型就会展开推理。但模型只展开一次，写完就结束。

推理模型是训练出来的行为：它被专门训练去 生成很长的思考、尝试多种解法、验证中间结果、发现错误后重来。 这个能力来自强化学习，不是靠提示词触发的。

两者的共同底层原理是一样的：把中间步骤写出来， 就为模型创造了更多的计算步骤。 第 3 章讲「深度带来表达能力」时说的是同一个道理—— 更多的串行计算步骤 = 更强的表达能力。 只是这次增加的不是层数，而是 token 数。

⚠什么时候不值得用推理模型

推理模型的代价是延迟和成本成倍上升。 一个简单问题它也可能想几千个 token。

不值得的场景： 闲聊、简单分类、信息抽取、格式转换、检索问答、 以及任何「答案唯一且明显」的任务。 这些任务上，推理模型的表现和普通模型没有区别， 但贵十倍、慢十倍。

值得的场景： 数学证明、复杂代码调试、多步规划、 需要权衡多个约束的决策、以及任何「想错了就全盘皆错」的任务。

工程上的常见做法是路由： 先用一个便宜的小模型判断问题难度， 简单问题走普通模型，难题才升级到推理模型。

21.5 多模态：从「读文字」到「看世界」

多模态的突破点其实很朴素： 把图像也变成一串 token。 一旦变成 token，剩下的事情就完全不用改—— 同样的注意力、同样的 Transformer、同样的训练目标。

流程可以概括成一句话： 切块 → 编码 → 投影到文本的向量空间 → 和文本 token 拼成一个序列。 之后模型根本不知道哪些 token 来自图片、哪些来自文字， 它只是在处理一个更长的序列。

模态怎么变成 token主要难点
图像 切成固定大小的 patch，每个 patch 过一个视觉编码器 分辨率与 token 数的矛盾：高清图会产生大量 token， 直接吃掉上下文预算
音频 按时间窗切片，每片编码成一个 token 采样率与时间粒度的权衡；连续语音的切分
视频 抽帧后按图像处理，加上时间维度的位置信息 token 数爆炸：1 分钟视频轻松上十万 token。 必须做抽帧、降分辨率、时间下采样
生成（图像/语音） 用离散化的表示（如 VQ-VAE 的码本）， 把生成问题变成「预测下一个 token」 离散化会损失细节；扩散模型与自回归是两条不同路线

多模态领域目前最明显的未解问题有三个： token 预算（视觉信息太占位置）、 细粒度理解（模型能看懂大致内容，但数不清图里有几个物体、 读不准小字）、 以及空间推理（理解「左边」「在……后面」这类关系仍然很弱）。

21.6 后训练的新范式：从「人类偏好」到「可验证奖励」

第 13 章讲的 RLHF 有一个根本瓶颈： 奖励来自人类（或人类训练的奖励模型）的判断，而人类判断是有噪声的。 对于「这段话是否礼貌」这种主观问题，人类能判断； 但对于「这段代码是否正确」，人类的判断慢且不可靠。

一个重要的转变是：在那些有客观正确答案的任务上， 直接用规则当奖励，而不需要奖励模型。

代码

跑单元测试。通过就是 1，失败就是 0。 奖励信号完全客观、无法被讨好。

数学

比对最终答案。答案对了给分， 过程对不对可以另算（用形式化验证更严格）。

结构化任务

格式校验、约束满足（如「必须包含 X 且不能包含 Y」）、 工具调用是否成功。

游戏 / 环境

胜负、得分、是否完成任务。 这类环境可以无限生成训练数据，不依赖人工标注。

这种模式通常被称为「用可验证奖励做强化学习」。 它解释了一个看起来矛盾的现象： 为什么模型在数学和代码上的提升速度，远快于在写作和常识上的提升速度？ 因为前者的奖励信号是干净的，后者不是。

⚠可验证奖励的两个隐患

① 奖励黑客（reward hacking）。 模型会找到「让检查通过」的捷径，而不是真的解决问题。 比如：把测试代码删掉让测试「通过」、 硬编码测试用例的答案、 在输出里塞满看起来像推理的文字。 奖励越简单，越容易被钻空子。

② 能力窄化。 如果后训练过度集中在可验证任务上， 模型可能变得「只会做题」—— 在开放对话、共情、创造性任务上反而变差。 这就是第 13 章讲过的「对齐税」的另一种形态。

工程上的应对是混合训练： 可验证任务（拿能力）+ 人类偏好数据（保风格与安全） 按比例混在一起，而不是只优化前者。

21.7 还没解决的问题

这一节我打算诚实地列一份清单。 前面二十章讲了很多「怎么做」，这里讲「哪些还做不到」。 理解边界，比记住结论更重要。

问题现状为什么难
幻觉无法根除 能降到 1%~3%，到不了 0 训练目标里没有「我不知道」这个选项； RLHF 又奖励自信。这是结构性的（见第 19 章）
可解释性 能定位「哪些 token 影响了输出」， 但说不清「模型到底学到了什么概念」 几亿个参数纠缠在一起，没有天然的模块边界。 我们至今不知道它为什么对，也就无法预测它什么时候会错
持续学习 训练完成后无法学习新知识。 想更新只能微调或 RAG 直接在旧数据上继续训练会导致灾难性遗忘。 如何在不遗忘的前提下增量学习，仍无通用解法
长程规划 几步到几十步的任务尚可， 上百步的可靠执行做不到 每一步的错误会累积。100 步、每步 99% 正确， 整体成功率只有 37%
评测的可信度 公开榜单与真实体验脱节， 模型可能「针对榜单优化」 评测集会被污染进训练数据； 开放式任务没有客观标准（见第 19 章）
推理效率 推理成本仍是应用规模化的主要瓶颈 本质受限于内存带宽——每次生成一个 token 都要把全部权重读一遍。 这是物理限制，不是算法问题
对齐的可靠性 安全训练可以显著降低有害输出， 但不能保证 对齐是在一个巨大的、开放的行为空间里做概率性约束。 总有没被覆盖到的输入分布
能源与成本 训练成本千万美元级，推理的能耗也在快速增长 目前提升能力的主要手段仍然是增加算力。 效率和能力之间还没有找到根本性的解耦方式
◆这份清单应该怎么用

不要把它当成「技术不行」的抱怨。它的实际用途是决策：

当有人告诉你「这个问题已经解决了」时，你可以核对这份清单。 幻觉被解决了吗？没有。可解释性被解决了吗？没有。 长程可靠性被解决了吗？没有。

然后做工程判断： 既然幻觉无法根除，我的系统就必须有一层校验； 既然长程规划不可靠，我就不能把上百步的流程完全交给它； 既然对齐不能保证，我就不能把不可逆操作的权限给它。

所有的系统设计，本质上都是在为这些已知的缺陷做补偿。

21.8 给学习者的建议：什么会变，什么不会变

这本书从第 1 章的线性回归写到这里。如果你一路读下来， 可能会有一个担忧：这些知识会不会很快过时？

我的判断是：具体的技术会快速变化，但底层原理变化很慢。 下面这张表是我的划分。

变化很快（不必深究细节）变化较慢（值得掌握）几乎不变（必须扎实）
具体模型的版本号与榜单分数
某个框架的 API
最新的提示词技巧
某个特定架构的超参数配方 		架构的演进方向（注意力变体、MoE、SSM）
训练与推理的工程实践
量化与部署手段
评测方法论 		梯度下降与反向传播
注意力的定义与计算
概率与信息论（交叉熵、困惑度）
缩放定律的基本形状
工程判断力（成本、可靠性、评测）

右边那一列之所以「不会变」，是因为它们是数学和工程事实， 不是产品决策。链式法则不会因为明年出了新模型就失效； 「没有评测的迭代是随机游走」这条经验也不会。

一个更重要的判断

随着模型越来越强，「模型能力」在工程里的权重会下降， 「工程判断」的权重会上升。

当模型很弱的时候，你要花大量精力去「让它能工作」—— 调提示词、试各种技巧。 当模型很强的时候，它自然就能工作， 而真正的难点变成了：

怎么知道它做得对不对（评测）、 怎么在它出错时不造成损害（可靠性）、 怎么让它和现有系统配合（集成）、 怎么控制成本（工程）。

这四件事，恰好都不是「模型知识」， 而是你在这本书后半部分读到的东西。 这也是为什么我花了那么多篇幅讲评测、幻觉、安全和可靠性， 而不是只讲架构。

接下来可以做什么

① 亲手实现一遍

把第 20 章的 mini-GPT 跑通，然后改它： 加一层、换激活函数、试试不同的学习率、 把字符级换成 BPE。 改动 → 观察 → 解释，这个循环是最高效的学习方式。

② 建一个小评测

把学到的东西写成文章或笔记。 写作会暴露你以为懂了但其实没懂的地方。 这是这本书能写成的原因，也是我给你的最后一个建议。

21.9 结语

回头看这二十一章，其实只讲了一件事： 如何让一个函数逼近另一个函数，并且只靠数据来调整它。

线性回归是最小的一步：两个参数，一条直线。 神经网络把它堆起来：更多的参数、非线性、更多的层。 反向传播解决了「怎么知道每个参数该往哪调」。 注意力解决了「怎么让信息在序列里自由流动」。 Transformer 把这两件事组合成一个可以无限堆叠、并且能高效并行训练的块。 然后我们把它放大到极限，用人类产生的全部文本去喂它， 再用人类的偏好去打磨它。

剩下的全是工程： 怎么把数据洗干净、怎么让梯度不爆炸、 怎么把显存塞进有限的卡里、怎么在几毫秒内出一个 token、 怎么知道它到底行不行、怎么在它出错的时候兜住。

最后一句

大模型不是一个神秘的智能，而是一台极其庞大的统计机器。

它做的每一件事，都可以还原成矩阵乘法、softmax 和梯度下降。 它让人惊叹的地方，不在于某一个零件有多聪明， 而在于这些简单的零件堆到足够多、数据喂到足够多之后， 涌现出了没有人逐行写下来的能力。

理解了这一点，你就不会再把它当成黑箱。 你会知道它的能力从哪来，也会知道它的边界在哪。 然后你可以真正地开始用它—— 不是祈祷它别出错，而是设计一个即使它出错也能用的系统。

这，就是这本书想给你的东西。

MoE 说「总参数 6000 亿，激活参数只有 600 亿」，这意味着什么？有什么代价？

意味着把「知识容量」和「计算量」解耦了。

稠密模型里，每处理一个 token，所有参数都要参与计算—— 参数和计算是绑死的。 MoE 把 FFN 拆成 N 个专家，每个 token 只激活 Top-K 个， 于是：

总参数（6000 亿）= 知识容量—— 模型有能力记住更多东西；
激活参数（600 亿）= 单次计算量—— 推理成本和 600 亿的稠密模型相当。

但代价是真实的，而且有三个：

① 通信开销。 专家分布在不同 GPU 上，token 要路由过去再传回来。 这个 all-to-all 通信经常比计算本身还慢， 是 MoE 部署最主要的瓶颈。

② 负载不均。 某个专家被大量 token 选中时，它所在的卡就成了木桶的短板。 而且如果路由失衡到极端（专家坍缩）， 那些闲置专家的参数永远得不到更新，等于白占显存。

③ 更吃显存。 总参数大，权重就要全部装进显存，即使某次推理用不到。 所以 MoE 的「便宜」是相对推理计算量而言， 不是相对显存而言。

一个直接推论：单卡部署场景下 MoE 基本没有优势， 它的价值在于「用多卡换更好的效果/成本比」。

上下文窗口有 1M token，是不是就可以把整个知识库塞进去了？

不建议，而且通常效果更差。

三个原因：

① 中间遗忘。 信息放在上下文里的位置决定了它能否被用上（第 18 章）。 长上下文里，中间位置的信息容易被忽略。 塞进去 200 页，不如精确检索出 5 段。

② 成本。 注意力是 O(n²)。窗口翻倍，计算量翻四倍， KV Cache 显存也翻倍。1M token 的上下文是极其昂贵的。

③ 噪声。 无关内容会稀释关键信息，模型更容易抓错重点。 检索的作用不仅是「找到相关的」， 也是「排除不相关的」。

那什么时候真的需要超长窗口？ 那些「你无法事先知道哪一段相关」的任务： 通读整个代码库做重构建议、分析整本小说的叙事结构、 跨文档做交叉引用核对。

判断标准很简单：如果你能提前知道要查什么， 就用检索；只有当相关性本身是未知的，才需要长窗口。

「让模型多想一会儿」为什么能提升准确率？它和思维链提示是什么关系？

因为更多的串行计算步骤 = 更强的表达能力。

这是第 3 章讲过的道理：一层网络只能拟合线性函数， 堆到足够深才能拟合任意复杂函数。 原因是每一层都提供了额外的串行计算步骤。

推理模型把同一件事搬到了 token 维度上： 模型每生成一个 token，都要完整地跑一遍所有层。 所以生成 5000 个思考 token， 相当于在深度方向上的计算量增加了 5000 倍 （代价是串行的，所以很慢）。 这个额外的计算被用来尝试不同解法、 检查中间结果、发现错误后重来。

和思维链提示的关系：

思维链是提示技巧——你在提示词里写 「让我们一步步思考」，模型就展开一次推理，写完就结束。

推理模型是训练出来的行为—— 它被专门训练去生成很长的思考、验证中间步骤、 在发现错误时回头重来。这个能力来自强化学习， 不需要提示词触发，而且长度可以远超一次思维链。

共同点是：把中间步骤写出来， 为模型创造更多计算步骤。这也是为什么「写出过程」 在两者中都是关键。

注意收益递减：每条曲线都会饱和。 而且简单任务上多想没有收益，只是白白烧钱—— 所以工程上通常按难度路由。

为什么模型在数学和代码上的进步速度，明显快于在写作和常识上？

因为奖励信号的干净程度不同。

数学和代码有客观的对错。 代码可以跑单元测试：通过是 1，失败是 0。 数学可以比对答案。这类奖励无法被讨好—— 模型不能靠「写得漂亮」蒙混过关。 于是强化学习可以非常高效地迭代： 生成大量候选 → 自动打分 → 强化高分的。 而且这个过程可以无限生成数据，不需要人工标注。

写作和常识没有客观标准。 「这段话是否得体」只能靠人类判断， 而人类判断有噪声、有分歧、成本高、无法规模化。 奖励信号是模糊的，强化学习的效率自然就低。

但这条路有两个隐患：

① 奖励黑客。 模型会找到「让检查通过」的捷径而不是真正解决问题—— 删掉测试代码让测试通过、硬编码测试用例的答案。 奖励越简单，越容易被钻空子。

② 能力窄化。 如果后训练过度集中在可验证任务上， 模型可能变得「只会做题」，在开放对话和共情上反而变差。

所以工程上的做法是混合训练： 可验证任务（拿能力）+ 人类偏好数据（保风格与安全） 按比例混在一起，而不是只优化前者。

如果只能从这本书里带走一件事，应该是什么？

如果只能带一件，我建议带走这个认知：

大模型的能力来自「简单零件 × 巨大规模」， 它的缺陷也来自同一件事。

能力侧：矩阵乘法、softmax、梯度下降—— 每个零件都简单到可以手算。 但堆到几十层、几千亿参数、几万亿 token 之后， 涌现出了没有人逐行写下来的能力。 这解释了为什么它能做那么多事，也解释了为什么 没有人能完整解释它为什么做对。

缺陷侧：因为是概率系统， 所以它会自信地编造（幻觉）； 因为它没有「我不知道」的训练信号， 所以它不会主动说不知道； 因为对齐是在开放空间里做概率约束， 所以它总会被绕过。

理解这一点，会直接改变你做事的方式：

你不会再去追求「消除幻觉」，而是设计校验层；
你不会再把不可逆操作的权限交给它，而是保留人在回路；
你不会再相信「我试了几个问题，感觉变好了」，而是先建评测；
你不会再指望提示词解决一切，而是知道边界在哪。

换句话说：你会从「祈祷它别出错」 变成「设计一个即使它出错也能用的系统」。 这个转变，是「会调模型」和「能做产品」之间的分界线。
