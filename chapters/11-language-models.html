第 11 章 · 第四部 注意力革命

语言模型与 GPT

GPT 的全部训练目标只有一句话：预测下一个词。 听起来简单到荒谬。但当这件事被做到万亿参数、几万亿 token 的规模时， 翻译、推理、写代码、做数学题这些能力会自己长出来。 这一章讲清楚这个「简单目标」为什么如此强大。

⏱ 约 32 分钟 🎯 理解语言模型、分词、困惑度与缩放律 🧪 1 个交互演示

11.1 语言模型：给句子打一个概率

一个语言模型做的事情，本质上就是回答一个问题： 这句话有多像人话？

$$P(\text{今天天气真好}) = 0.0083$$ $$P(\text{真好天气今天}) = 0.00000012$$

它给任何一段文本赋予一个概率。像人话的概率高，不像人话的概率低。

但直接给整个句子打分很难，因为句子的数量是天文数字。 所以实践中我们用一个数学恒等式把它拆开——链式法则：

$$P(w_1, w_2, \ldots, w_n) = \prod_{t=1}^{n} P(w_t \mid w_1, \ldots, w_{t-1})$$
整句话的概率 = 每个词在「它之前所有词」条件下的概率之积

这个式子看起来只是把问题变复杂了，但它带来了一个决定性的好处： 每个因子都是同一个形式的问题——「给定前文，下一个词是什么」。

GPT 的全部秘密

把「理解语言」这件宏大而模糊的事，化简成「预测下一个 token」这件具体而可测量的事。

而这个任务有个绝妙的性质：答案就在数据里，不需要人工标注。 任何一段文本，「今天天气真」的答案就是「好」。 互联网上有几十万亿 token 的文本，每一段都自动变成一道训练题。

这就是第 1 章说的「自监督学习」，也是大模型时代真正的起点。

11.2 从 n-gram 到神经网络

「给定前文预测下一个词」这个任务其实非常古老。在神经网络之前， 人们用的是 n-gram：只看前面 $n-1$ 个词，数一数语料里出现过多少次。

n-gram 有三个致命问题，正好对应神经网络的三个优势：

问题n-gram神经网络
上下文太短 通常只看 2~5 个词。看到「我出生在法国，所以我说一口流利的」， 它看不到 10 个词之前的「法国」 可以看几千到几百万个 token
数据稀疏 「量子纠缠很」这种组合语料里没出现过，概率就是 0 用连续向量表示，能泛化到没见过的组合
参数爆炸 词表 5 万，看 5 个词就要 $50000^5$ 种组合，根本存不下 参数量只和模型维度、层数有关，与上下文长度无关

第二点尤其重要。n-gram 把每个词当作一个独立的符号， 而神经网络把词映射成连续的向量。 于是「猫」和「小猫」在向量空间里离得很近， 模型在「猫 喜欢 吃 鱼」上学到的规律，能部分迁移到「小猫 喜欢 吃 鱼」。

这种「用连续向量表示离散符号」的思想，就是词嵌入（word embedding）。

11.3 分词：模型眼里的文字长什么样

模型不认识「文字」，只认识数字。所以第一步要把文本切成 token 再映射成 ID。 这个看似琐碎的环节，实际上深刻影响着模型的能力。

⚠分词带来的三个真实问题

1. 算术能力差。模型看到的不是「1234」而是 123+4 这样的碎片，它根本不知道这是一个四位数。 这被认为是 LLM 数学能力弱的一个重要原因。

2. 中英文成本不同。同样一段话，中文和英文消耗的 token 数不一样。 这直接影响 API 计费和多语言能力的均衡性。

3. 拼写任务困难。问模型「strawberry 里有几个 r」， 它看到的是 straw+berry，数不清字母。 这不是「模型笨」，而是它压根看不到字符级别的东西。

11.4 训练目标：next token prediction

现在我们有了 token 序列，模型要做的事情就非常清晰了。给定一段文本：

模型对每一个位置都输出一个词表大小的概率分布， 然后我们要求「正确答案」那一项的概率尽可能大。

注意这里一个极其优雅的地方：一段长度为 $n$ 的文本，同时提供了 $n$ 个训练样本。 位置 1 预测位置 2，位置 2 预测位置 3……全都算作损失。 这就是为什么大模型能用同样的数据量获得极高的训练效率。

训练目标的构造。输入和目标只差一个位置的平移。 一次前向传播就能同时得到 $n$ 个预测，全部参与损失计算。

11.5 损失函数：交叉熵与困惑度

语言模型用的损失是交叉熵（cross-entropy）。它衡量的是 「模型给正确答案分配的概率有多低」：

$$L = -\frac{1}{N}\sum_{i=1}^{N} \log P(w_i \mid w_{<i})$$
对每个位置，取正确答案概率的对数，加负号，然后求平均

这个式子的行为很符合直觉：

  • 如果模型给正确答案 0.9 的概率，损失是 $-\log 0.9 = 0.105$——很小。
  • 如果只给 0.1 的概率，损失是 $-\log 0.1 = 2.303$——很大。
  • 如果给 0.001 的概率，损失是 6.9——惩罚非常重。

注意这里是对数：概率越低，损失增长得越快。 这迫使模型不敢完全排除任何一个可能的答案。

困惑度：一个更好理解的指标

交叉熵的数值不太直观，所以人们常把它取指数，得到困惑度（perplexity, PPL）：

$$\text{PPL} = e^{L}$$
可以理解为「模型在每一步平均在多少个候选词之间犹豫」
交叉熵困惑度含义
9.2110000随机猜（词表 10000 个词，均匀分布）
4.60100非常差的模型
2.3010一般水平
1.615不错
0.692非常好的模型（现代大模型的水平）

现代大模型在英文上的困惑度通常在 2~5 之间。这意味着模型每预测一个词， 平均只在两三个候选之间犹豫——这已经接近人类水平了。

∑为什么困惑度有下界？

语言本身是有随机性的。看到「今天天气真」，下一个字可能是 「好」「不错」「差」「冷」……没有人能 100% 确定。

这个内在的不确定性叫语言熵。英语的熵大约在 1.0~1.5 nats 左右， 所以困惑度的理论下界大概是 $e^{1.0} \approx 2.7$。 一个模型如果真的把困惑度降到 1.0，那说明它在训练集上过拟合了。

11.6 缩放律：深度学习最重要的经验规律

2020 年，OpenAI 的 Kaplan 等人发现了一个惊人的规律： 模型的性能（损失）随着规模的增长，呈现出极其平滑的幂律关系。

$$L(N, D, C) = \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}} + L_\infty$$
$N$ 是参数量，$D$ 是数据量，$C$ 是算力。$\alpha \approx 0.076$，$\beta \approx 0.095$
缩放律。在双对数坐标下，损失几乎是一条直线。 这意味着我们可以用较小的实验外推预测大模型的效果—— 不需要真的训练一个万亿参数模型，也能知道它大概能到什么水平。

缩放律有几个极其重要的实践含义：

  1. 投入是值得的。不存在「模型变大就没用了」的拐点—— 至少到目前还没有看到。这直接支撑了行业里几百亿美元级别的算力投入。
  2. 可以提前预测。先跑一批小规模实验， 拟合出幂律曲线，就能预测大模型的最终效果，据此决定要不要投入。
  3. 参数量和数据量要一起涨。 2022 年的 Chinchilla 论文修正了 Kaplan 的结论： 当时的大模型训练数据都太少了。 最优的配比是「每个参数大约对应 20 个 token」。

Chinchilla 的结论是「在给定算力预算下，损失最小」的配比。 但训练完之后，模型要反复被推理几亿次。

推理成本正比于参数量，与训练数据量无关。 所以用「多喂数据、少堆参数」的方式，虽然训练时多花了点算力， 但换来一个更小更快的模型——从总拥有成本看划算得多。

这就是为什么 LLaMA 用 7B 参数吃了 2T token， 而它的效果能追上当年 175B 的 GPT-3。数据比参数更值钱。

11.7 涌现能力：量变引起质变

如果缩放律只是「平滑变好」，那它只是工程上的好消息。 但研究者发现了一件更奇怪的事：某些能力会突然出现。

涌现能力（Emergent Abilities）。某些任务上，模型在小规模时表现接近随机， 规模跨过某个阈值后准确率突然跃升到可用水平。

典型的涌现能力包括：

少样本学习

给几个例子就能做新任务，不需要微调。GPT-3 首次展示了这一点。

思维链推理

「让我们一步步思考」能显著提升数学和逻辑题的正确率。小模型上完全无效。

指令遵循

理解并执行复杂、多步骤的自然语言指令，包括隐含的约束。

代码与工具使用

写可运行的代码、调用 API、按格式输出结构化数据。

⚠对「涌现」的一个必要的怀疑

2023 年有论文指出：涌现现象部分可能是度量方式造成的假象。 如果你用「完全正确才算对」这种严格指标，小模型几乎永远是 0 分， 跨过阈值后才开始有分——看起来就像突然跃升。 但如果改用「部分正确」的连续指标，曲线其实是平滑的。

所以「涌现」是否真实存在仍有争论。但无论机制如何， 「大规模模型能做到小模型完全做不到的事」这个现象是真实且重要的。

11.9 自回归生成：一个字一个字地写

训练完之后，怎么用它生成文本？过程叫自回归生成：

  1. 给一个提示（prompt）

    比如「从前有座山」。

  2. 前向传播，得到一个概率分布

    模型输出词表里每个 token 的概率，比如「里」0.4、「上」0.2、「，」0.1……

  3. 从分布里采样一个 token

    不是直接取概率最高的，而是按概率随机抽——这样生成才有变化。

  4. 把它接到输入后面，重复

    输入变成「从前有座山里」，继续预测下一个。

每一步都要完整跑一遍前向传播。这意味着生成 500 个 token， 就要跑 500 次模型——这是 LLM 推理慢的根本原因。 第 14 章会讲 KV Cache 等加速手段。

✓temperature 和 top_k 在做什么

temperature 在 softmax 之前把 logits 除以 $T$：
· $T < 1$ → 分布更尖锐，输出更确定、更保守（适合代码、数学）
· $T > 1$ → 分布更平坦，输出更随机、更有创意（适合写诗、头脑风暴）
· $T = 0$ → 退化成贪心搜索，每次选概率最高的词

top_k 只从概率最高的 $k$ 个候选里采样， 直接砍掉长尾里的荒谬选项。这两个参数是同一个目的： 在「不重复」和「不胡说」之间找平衡。

第 14 章会详细讲采样策略（还包括 top-p、重复惩罚、beam search 等）。

交互 15softmax 与温度：分布是怎么被「拧」出来的
logit · 猫3.0
logit · 狗2.5
logit · 鱼1.0
logit · 汽车-0.5

模型输出的是 logits（未归一化的分数）， 经过 softmax(logits / T) 才变成概率。 拖动温度，观察两件事：分布的形状和 熵（不确定性）。温度越低，分布越尖锐、熵越小、 输出越确定；温度越高，分布越平坦、熵越大、输出越随机。 这就是「同一个模型，换个温度就像换了个性格」的原因。

为什么「预测下一个词」这个简单目标能产生翻译、推理等复杂能力？

因为要准确预测下一个词，模型必须理解产生这个词的全部上下文。

举例：「我出生在法国，十岁搬到日本，所以我的母语是___」。 要填对「法语」，模型必须做实体识别（法国）、理解因果关系（出生地→母语）、 还要抵抗更近的干扰项（日本）。

这不是一个简单的任务——它隐式地包含了几乎所有语言理解任务。 为了让损失下降，模型被迫学会语法、语义、常识、逻辑， 因为这些都会影响下一个词是什么。

所以「简单」只是表面。真正的关键是：这是一个足够难、又足够可测量的目标函数。

如果模型的困惑度是 1.0，说明什么？

困惑度 1.0 意味着交叉熵为 0，也就是模型对每一个下一个词都给出了概率 1.0。

这在真实数据上不可能发生，因为语言本身有内在的随机性—— 看到「今天天气真」，下一个字可能是「好」「差」「热」， 没有人能 100% 确定。英语的内在熵大约在 1.0 nats 左右， 所以困惑度的理论下界大约是 $e^{1.0} \approx 2.7$。

如果真的测出 1.0，唯一的解释是过拟合或数据泄漏： 模型见过这些数据（或者测试集和训练集重叠了）， 它是「背」出来的而不是「理解」出来的。

为什么中文的一个字通常是 1 个 token，而英文的一个词可能是 2~3 个？

因为 BPE 是按字节和频率工作的，而一个汉字 在 UTF-8 里占 3 个字节，携带的信息量接近一个英文单词。

训练语料里，常用的汉字出现频率极高，很快就被合并成单个 token。 而英文的长词（比如 tokenization）虽然整体出现频率不高， 但它的组成碎片（token、ization）在其他词里反复出现， 所以会被拆成 2~3 个 token。

实际后果是：同样一段语义内容，中文消耗的 token 通常比英文少， 但因为中文 token 的「信息密度」更高，模型对每个中文 token 的建模难度也更大。 这是多语言模型需要专门平衡的一个问题。

Chinchilla 的结论是什么？为什么后来的模型不遵守它？

结论：在给定算力预算下，参数量和数据量应该等比例增长， 大约每个参数配 20 个 token 时损失最小。 当时的大模型（比如 GPT-3）数据量严重不足，属于「大而无当」。

为什么不遵守：Chinchilla 优化的是「训练结束时的损失」， 但模型的真实成本还包括推理。推理成本正比于参数量， 与训练数据量无关。

所以如果总预算有限，用「小模型 + 海量数据」的策略更划算： 训练时多花一点，但换来一个更小更快的模型， 在后续几亿次的推理中把成本赚回来。 LLaMA-7B 用 2T token（约 286 token/参数）就是这种思路的产物。

为什么问 GPT「strawberry 里有几个 r」，它经常答错？

因为它根本看不到字母。

模型看到的是 token，而 strawberry 在 GPT 的分词器里可能被切成 str + aw + berry 这样的碎片。 它拿到的是 3 个整数 ID，而不是 10 个字符。

「数有几个 r」是一个字符级操作， 而模型的表示里压根没有字符这一层。它只能靠记忆里的相似模式去猜。

这不是「模型不够聪明」，而是表示层面的限制。 解决办法包括：改用字符级处理、让它写代码来数、 或者用「思考型」模型在推理时展开中间步骤。
